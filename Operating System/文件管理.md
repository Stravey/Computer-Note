### 文件管理知识体系梳理

文件管理是操作系统（OS）五大功能之一，主要负责管理外存上的文件，并为用户和应用程序提供高效、便捷的文件访问接口。其核心可以概括为：**“文件如何存”** 和 **“磁盘如何管”**。

------

#### 一、 文件系统基础

1. **文件的概念**
   - **定义**：具有文件名的一组相关信息的集合。是外存分配的基本单位。
   - **属性**：文件名、标识符（唯一的内部ID）、类型、位置、大小、保护信息、时间日期等。
   - **操作**：创建、读、写、删除、截断、打开(`open`)、关闭(`close`)等。`open`调用会将文件的元数据载入内存的**打开文件表**，避免后续操作重复检索目录，提升效率。
2. **文件的逻辑结构** (用户视角)
   - **无结构文件（流式文件）**：文件内容是一系列二进制或字符流。如文本文件、可执行文件。
   - **有结构文件（记录式文件）**：
     - **顺序文件**：记录按某种顺序排列。如果是串结构（顺序与关键字无关），则查找只能顺序遍历；如果是顺序结构（按关键字排序），则可使用折半查找等高效算法。
     - **索引文件**：为文件建立一个索引表，每个记录对应一个索引项（包含关键字和指向记录的指针）。适合随机访问，但会增加存储开销。
     - **索引顺序文件**：是顺序文件和索引文件的折中。先将记录分组，为每组第一个记录建立索引项。先查索引找到组，再在组内顺序查找。大大提高了查找效率。
   - **与《数据结构》的联系**：文件的逻辑结构本质是**线性表**在磁盘上的实现。顺序文件对应顺序表，索引文件对应索引表或散列表的思想。
3. **目录结构** (如何组织文件)
   - **文件控制块（FCB）**：存放文件元数据的数据结构。**目录本身就是一种有结构文件**，其每条记录就是一个文件的FCB。
   - **目录结构**：
     - **单级目录**：整个系统只有一个目录，存在命名冲突、查找效率低等问题。
     - **两级目录**：为每个用户创建一个独立的目录，解决了命名冲突。
     - **多级目录（树形目录）**：现代OS主流结构。路径清晰，便于分类和管理。允许**绝对路径**和**相对路径**。
     - **无环图目录**：允许文件或目录被多个目录共享。通过**链接**（软链接或硬链接）实现。需要额外的机制（如引用计数）来管理磁盘空间的释放。
   - **与《数据结构》的联系**：目录结构是**树**（多级目录）和**图**（无环图目录）这两种数据结构的直接应用。
4. **文件共享与保护**
   - **共享**：
     - **基于索引节点的共享（硬链接）**：多个目录项指向同一个索引节点（i-node）。索引节点中有引用计数，只有当计数为0时文件才被真正删除。
     - **利用符号链实现共享（软链接）**：创建一个特殊文件（Link文件），其内容是目标文件的路径名。删除原文件会导致软链接“悬空”。
   - **保护**：
     - **访问类型**：读、写、执行、添加、删除、列表等。
     - **访问控制**：使用**访问控制列表（ACL）**，为每个文件列出用户/用户组及其权限。或者使用精简的**权限位**（如Unix的`rwx`位）。

------

#### 二、 文件系统的实现 (系统视角)

1. **文件的物理结构（分配方式）** (核心中的核心)
   - **连续分配**：为文件分配一组连续的磁盘块。
     - **优点**：支持顺序访问和随机访问（可直接计算地址），速度快。
     - **缺点**：会产生**外部碎片**，文件长度不易动态增长。
   - **链接分配**：
     - **隐式链接**：每个块包含一个指向下一个块的指针。
       - **优点**：无外部碎片，可动态增长。
       - **缺点**：只能顺序访问，可靠性差（一个指针出错全盘皆输）。
     - **显式链接**：把用于链接文件的指针显式地存放在内存的一张**文件分配表（FAT）** 中。
       - **优点**：支持随机访问（通过查FAT在内存中遍历链），提高了速度。
       - **缺点**：FAT表需要占用较大的内存空间。
   - **索引分配**：为每个文件建立一个**索引块**，索引块中的每个表项指向文件的一个物理块。
     - **优点**：既支持顺序访问也支持随机访问，无外部碎片。
     - **缺点**：索引块本身需要占用存储空间。
     - **优化策略**（解决大文件索引问题）：
       - **链接方案**：将多个索引块链接起来。
       - **多级索引**：建立索引块的索引块（如Unix/Linux的i-node结构）。
       - **混合索引**：**最常考！** 如i-node中既包含直接地址（指向数据块），又包含一级间接地址、二级间接地址等。这种结构是小文件高效、大文件可行的完美折中。
2. **存储空间管理** (磁盘空闲块的管理)
   - **空闲表法**：适用于连续分配，类似内存管理的动态分区分配。
   - **空闲链表法**：将所有空闲块链接起来。
   - **位示图法**：**最常用！** 用一串二进制位（`0`空闲，`1`已分配）来表示磁盘块的使用情况。`字号`和`位号`可以很容易地换算成物理块号。
     - `块号 = 字号 * (字长) + 位号`
     - `字号 = 块号 / (字长)`
     - `位号 = 块号 % (字长)`
   - **成组链接法**：UNIX系统采用的方法，适合大型文件系统。是空闲链表法和索引法的结合，将空闲块分组，组间链接，组内用索引表。
3. **磁盘调度算法** (提高I/O效率)
   - **目标**：减少平均寻道时间。
   - **先来先服务（FCFS）**：公平但性能差。
   - **最短寻找时间优先（SSTF）**：选择离当前磁头最近的请求。可能产生**饥饿**现象。
   - **扫描算法（SCAN，电梯算法）**：磁头在一个方向上移动，服务所有经过的请求，到另一端后反向。
   - **循环扫描算法（C-SCAN）**：类似SCAN，但只在一个方向上服务，返回时直接快速复位到起点，不服务任何请求。提供了更均匀的等待时间。
   - **LOOK与C-LOOK算法**：SCAN和C-SCAN的改进，磁头只需移动到最远的一个请求即可立即返回，无需移动到磁盘端点。
4. **磁盘的管理**
   - **磁盘初始化**：低级格式化->分区->逻辑格式化（创建文件系统）。
   - **引导块**：计算机启动时，ROM中的引导程序会从固定的**引导块**（通常是0号块）读取更复杂的启动程序（如OS的引导程序）到内存。
   - **坏块**：由磁盘控制器管理的缺陷扇区。

### 与其他知识点的关系

#### 1. 与**操作系统内部**的关系

- **内存管理**：
  - **目标相似性**：两者都管理分层存储体系中的一层（内存 vs. 外存），都涉及分配、回收、地址转换、空间保护等问题。
  - **技术联动**：**虚拟内存**技术是内存管理和文件管理结合的典范。Swap area（交换区）就是一个特殊的文件，页面的换入换出就是文件I/O操作。文件系统的**缓存/缓冲机制**（Buffer Cache）也直接依赖于内存空间。
- **设备管理**：
  - 文件系统是设备管理的**上层用户**。所有对文件的最终操作，都要通过设备管理程序（I/O子系统、设备驱动程序）转换成对磁盘控制器和磁盘硬件的具体指令（如CHS或LBA地址）。磁盘调度算法是设备管理中调度算法的具体应用。

#### 2. 与**计算机组成原理**的关系

- **存储层次结构**：文件管理直接对应**辅助存储器**（磁盘、SSD）的管理。需要理解磁盘的**物理结构**（柱面、磁道、扇区）、**访问时间**（寻道时间、旋转延迟、传输时间）等概念，这些是组成原理的重点。
- **I/O系统**：文件读写最终体现为**I/O操作**。需要理解**DMA（直接存储器存取）** 方式如何在不占用CPU的情况下完成数据在磁盘和内存之间的传输，这极大提升了文件操作的效率。
- **数据的表示与存储**：文件的存储本质上是在外存上的一系列**二进制位**的组织。理解字节、块、扇区等存储单位及其关系至关重要。

#### 3. 与**数据结构**的关系

- **无处不在的数据结构**：文件系统的实现大量使用了经典数据结构。
  - **线性表**：文件的逻辑结构、目录项列表、FAT表。
  - **链表**：隐式/显式链接分配、空闲链表法。
  - **树**：多级目录结构、多级索引。
  - **图**：无环图目录结构。
  - **位数组**：位示图法。
  - **哈希表**：在某些文件系统中用于快速查找文件。
- **算法应用**：查找目录、管理空闲空间、磁盘调度等都需要高效的算法支持。
