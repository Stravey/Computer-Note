# 经典同步问题

### **1. 生产者-消费者问题 (The Producer-Consumer Problem)**

#### **问题描述**：

- **生产者**进程生产数据，并放入一个**固定大小**的缓冲区。
- **消费者**进程从缓冲区取出数据并消费。
- **规则**：
  1. **互斥**：生产者与生产者、消费者与消费者、生产者与消费者之间必须互斥地访问缓冲区（一次只有一个进程操作缓冲区）。
  2. **同步**：
     - 缓冲区**满**时，生产者必须等待消费者（空位同步）。
     - 缓冲区**空**时，消费者必须等待生产者（产品同步）。

#### **信号量设置**：

- **互斥信号量** `mutex`：初值为1，用于保证互斥访问缓冲区。
- **同步信号量** `empty`：初值为N（缓冲区大小），表示当前空闲缓冲区的数量（空位资源）。
- **同步信号量** `full`：初值为0，表示当前已使用的缓冲区数量（产品资源）。

#### **代码实现**：

```c++
semaphore mutex = 1;   // 互斥锁
semaphore empty = N;   // 空缓冲区数量
semaphore full = 0;    // 满缓冲区数量（产品数量）

producer() {
    while(1) {
        produce an item;           // 生产一个产品
        P(empty);                 // 申请一个空位（空位-1）。若empty=0，则阻塞等待
        P(mutex);                 // 申请进入临界区（锁上缓冲区）
        add the item to buffer;   // 将产品放入缓冲区
        V(mutex);                 // 离开临界区（解锁缓冲区）
        V(full);                  // 增加一个产品（产品+1），并唤醒可能等待的消费者
    }
}

consumer() {
    while(1) {
        P(full);                  // 申请一个产品（产品-1）。若full=0，则阻塞等待
        P(mutex);                 // 申请进入临界区（锁上缓冲区）
        remove an item from buffer; // 从缓冲区取出一个产品
        V(mutex);                 // 离开临界区（解锁缓冲区）
        V(empty);                 // 增加一个空位（空位+1），并唤醒可能等待的生产者
        consume the item;         // 消费该产品
    }
}
```

#### **⚠️ 关键注意点**：

- **P操作的顺序至关重要**。必须先对资源信号量（`empty`, `full`）进行P操作，再对互斥信号量（`mutex`）进行P操作。
  - **错误顺序**：如果先 `P(mutex)` 再 `P(empty)`，假设缓冲区已满，生产者先拿到锁，然后发现 `empty=0` 而阻塞。它持有锁进入睡眠，导致消费者也无法进入临界区取走产品，从而形成**死锁**。
- **V操作的顺序**可以交换，因为V操作不会导致进程阻塞。

### **2. 读者-写者问题 (The Readers-Writers Problem)**

#### **问题描述**：

- **写者**进程要求**独占**地读写共享数据（如数据库记录）。
- **读者**进程可以与其他读者**同时**读取共享数据。
- **规则**：
  1. **互斥**：写者与任何其他进程（读者或写者）必须互斥地访问数据。
  2. **同步**：允许多个读者同时读。

#### **信号量设置 (读者优先方案)**：

- **互斥信号量** `wrt`：初值为1，用于保证写者之间、写者与读者之间的互斥。
- **互斥信号量** `mutex`：初值为1，用于保证对计数器 `readcount` 的互斥访问。
- **整型变量** `readcount`：记录当前正在读的读者数量。

#### **代码实现 (读者优先)**：

```c++
semaphore wrt = 1;     // 写者锁，保证写互斥
semaphore mutex = 1;   // 用于保护readcount的互斥锁
int readcount = 0;     // 正在读的读者数量

writer() {
    while(1) {
        P(wrt);           // 申请写锁
        // writing is performed // 执行写操作
        V(wrt);           // 释放写锁
    }
}

reader() {
    while(1) {
        P(mutex);              // 锁住readcount
        readcount++;
        if (readcount == 1) {  // 如果是第一个读者
            P(wrt);            // 申请写锁，阻止写者
        }
        V(mutex);              // 释放readcount锁

        // reading is performed // 执行读操作

        P(mutex);              // 锁住readcount
        readcount--;
        if (readcount == 0) {  // 如果是最后一个读者
            V(wrt);            // 释放写锁，允许写者进入
        }
        V(mutex);              // 释放readcount锁
    }
}
```

**“读者优先”的含义**：只要还有读者在读，后续的读者就可以直接进入，写者会持续等待，可能导致**写者饥饿**。

#### **写者优先方案 (了解概念)**

- **目标**：一旦有写者准备写，它应该尽快开始写，后续的读者必须等待。
- **实现**：需要更复杂的机制，通常引入额外的信号量（如 `rwt`）来阻止新读者在写者等待时加入。代码比读者优先复杂，408考察实现代码的概率较低，但需理解其思想。

### **3. 哲学家进餐问题 (The Dining Philosophers Problem)**

#### **问题描述**：

- 5个哲学家围坐一桌，中间是一碗米饭，桌上放着5根筷子。
- 哲学家只有两种活动：**思考**和**吃饭**。
- 吃饭时需要同时拿起**左右两边的筷子**（两根资源）才能开始。
- 如何协调，保证哲学家们能顺利吃饭，且不会出现死锁或饥饿？

#### **信号量设置 (初步有问题的方案)**：

- **信号量数组** `chopstick[5]`：初值均为1，每根筷子一个信号量。

#### **代码实现 (有死锁的方案)**：

```c++
semaphore chopstick[5] = {1,1,1,1,1};

philosopher_i() { // i from 0 to 4
    while(1) {
        think();                     // 思考
        P(chopstick[i]);            // 拿起左边的筷子
        P(chopstick[(i+1) % 5]);    // 拿起右边的筷子
        eat();                      // 进餐
        V(chopstick[i]);            // 放下左边的筷子
        V(chopstick[(i+1) % 5]);    // 放下右边的筷子
    }
}
```

**问题**：如果所有哲学家同时感到饥饿，同时拿起左边的筷子，会导致 `chopstick` 全部为0。当每个哲学家试图拿起右边的筷子时，都会因无法获取而无限等待，导致**死锁**。

#### **解决方案**：

1. **限制同时吃饭的人数**：最多只允许4个哲学家同时去拿筷子。这样至少能保证有一个哲学家可以拿到两根筷子。

   ```c++
   semaphore count = 4; // 最多允许4个人同时拿筷子
   philosopher_i() {
       while(1) {
           think();
           P(count);                // 申请吃饭名额
           P(chopstick[i]);
           P(chopstick[(i+1)%5]);
           eat();
           V(chopstick[i]);
           V(chopstick[(i+1)%5]);
           V(count);                // 释放吃饭名额
       }
   }
   ```

2. **资源分级法**：为所有筷子编号（0-4）。哲学家必须**先拿编号小的筷子，再拿编号大的筷子**。（或者相反）

   ```c++
   philosopher_i() {
       while(1) {
           think();
           if (i % 2 == 0) { // 偶数号哲学家：先左后右
               P(chopstick[i]);
               P(chopstick[(i+1)%5]);
           } else {          // 奇数号哲学家：先右后左
               P(chopstick[(i+1)%5]);
               P(chopstick[i]);
           }
           eat();
           V(chopstick[i]);
           V(chopstick[(i+1)%5]);
       }
   }
   ```

   这种方法破坏了循环等待条件，从而避免死锁。

3. **AND型信号量**：操作系统提供一种原语，可以一次性分配或释放所有所需资源。哲学家进程要求同时分配左右两根筷子。

   // Seat(chopstick[i], chopstick[(i+1)%5]);

### **4. 吸烟者问题 (The Cigarette Smokers Problem)**

#### **问题描述**：

- 一个系统中有三个**吸烟者**进程和一个**供应者**进程。
- 每个吸烟者**无限循环**地卷烟、吸烟。卷烟需要三种材料：**烟草、纸、胶水**。
- **每个吸烟者只拥有其中一种材料**（吸烟者1有烟草，吸烟者2有纸，吸烟者3有胶水）。
- 供应者无限循环地随机提供**两种材料**（桌上放两种，缺一种），并唤醒拥有所缺材料的吸烟者。
- 吸烟者卷起烟吸烟，吸完后通知供应者，供应者再放下两种材料。

#### **信号量设置**：

- `offer1`：代表“烟草和纸”组合就绪的信号。初值为0。
- `offer2`：代表“烟草和胶水”组合就绪的信号。初值为0。
- `offer3`：代表“纸和胶水”组合就绪的信号。初值为0。
- `finish`：代表吸烟者是否完成的信号。初值为0，用于通知供应者可以放下下一组材料。

#### **代码实现**：

```c++
semaphore offer1 = 0, offer2 = 0, offer3 = 0;
semaphore finish = 0;
int i = 0; // 用于随机数

provider() {
    while(1) {
        i = rand() % 3;
        if (i == 0) {
            V(offer1); // 提供烟草和纸，唤醒有胶水的吸烟者3
        } else if (i == 1) {
            V(offer2); // 提供烟草和胶水，唤醒有纸的吸烟者2
        } else {
            V(offer3); // 提供纸和胶水，唤醒有烟草的吸烟者1
        }
        // 将材料放在桌子上
        P(finish); // 等待吸烟者吸烟完成
    }
}

smoker1() { // 拥有烟草
    while(1) {
        P(offer3);      // 等待纸和胶水
        // 取走材料，卷烟，吸烟
        V(finish);      // 通知供应者完成
    }
}

smoker2() { // 拥有纸
    while(1) {
        P(offer2);      // 等待烟草和胶水
        // 取走材料，卷烟，吸烟
        V(finish);      // 通知供应者完成
    }
}

smoker3() { // 拥有胶水
    while(1) {
        P(offer1);      // 等待烟草和纸
        // 取走材料，卷烟，吸烟
        V(finish);      // 通知供应者完成
    }
}
```

**核心思想**：供应者通过不同的信号量**精准唤醒**某个特定的吸烟者进程。
