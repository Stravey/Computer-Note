# 中断全流程

### 中断处理详细步骤

#### 第零步：中断请求（Interrupt Request）

- **触发**：某个中断源（如I/O设备、时钟、软件异常）需要CPU介入处理时，会向CPU的中断控制器发出一个中断请求信号。
- **记录**：中断控制器会记录这个请求。
- **条件**：CPU**不是**立刻响应，只有在满足特定条件时才响应：
  1. CPU允许中断（即中断允许触发器 `EINT = 1`，通常由“开中断”指令设置）。
  2. 当前指令执行完毕。
  3. 没有更高级的请求（如DMA请求）发生。
  4. 当前中断的优先级高于正在运行程序的优先级。

#### 第一步：中断响应（Interrupt Acknowledge）

- 当上述条件满足后，CPU进入**中断周期**。
- CPU会发出**中断响应信号**给中断控制器。
- **关键操作**：由**硬件**自动完成一系列“隐式”操作，这是考试重点：
  1. **关中断**：为了防止在保存现场过程中被新的中断打断，硬件会自动将 `EINT` 置为 0。
  2. **保存断点**：将**当前程序计数器（PC）** 的内容（即下一条即将要执行的指令的地址，称为“断点”）压入**系统栈**（通常是内核栈）保存。**注意：** 有些架构可能使用固定的内存单元或专用寄存器，但现代通用系统通常压栈。
  3. **转入中断服务程序**：中断控制器会提供一个**中断类型号**（或向量号），CPU根据这个号码，去查询**中断向量表**（Interrupt Vector Table, IVT），从中找到对应中断服务程序（ISR）的入口地址，并装入PC。至此，CPU开始执行ISR的第一条指令。

#### 第二步：中断服务程序执行（ISR Execution）

- 这一步主要由**软件**（操作系统内核代码）完成，但开头部分可能需要硬件辅助。
- **1. 保护现场**：
  - ISR的第一段代码会负责将**程序状态字（PSW）** 和所有可能被ISR修改的**通用寄存器**的内容压入堆栈。这是因为ISR本身也需要使用这些寄存器，为了保护被中断程序的数据，必须保存。
  - **注意区分**：“保存断点”（PC值）是**硬件**自动完成的；“保护现场”（寄存器等）是**软件**（ISR）完成的。
- **2. 开中断**（可选，用于实现中断嵌套）：
- 
  - 如果ISR允许被更高级的中断打断，此时会执行一条“开中断”指令（如 x86 的 `STI`）。
- **3. 执行核心处理逻辑**：
  - 执行该中断请求需要的具体操作，例如从I/O端口读取数据、处理时钟信号、处理页面故障等。
- **4. 关中断**（如果之前打开了）：
  - 为保证后续“恢复现场”操作不被打断，需要再次关中断。
- **5. 恢复现场**：
  - 将之前压栈的通用寄存器和PSW的值，按相反顺序弹出栈，恢复到各自的寄存器中。
- **6. 开中断**：
  - 通常由一条“中断返回”指令自动完成。
- **7. 中断返回**：
  - 执行一条**中断返回指令**（如 x86 的 `IRET`）。这条指令会由**硬件**自动完成两项工作：
    a. **恢复断点**：从栈中弹出断点地址，送回PC。
    b. **恢复PSW**：同时恢复原程序的PSW（包括开中断状态）。

#### 第三步：返回原程序

- CPU接着从断点处开始执行原来的程序，就像什么都没有发生过一样。

### 关键考点与易混淆点（408 最爱考！）

1. **硬件完成 vs. 软件完成**
   - **硬件自动完成（隐式操作）**：**中断响应周期**内完成的工作。包括：**关中断、保存断点（PC）、引出ISR（查中断向量表）**。
   - **软件（ISR）完成**：**保护现场（寄存器）、处理中断、恢复现场、开中断、中断返回**。虽然“中断返回”是指令，但其具体操作（弹PC和PSW）是硬件实现的。
2. **保存断点 vs. 保护现场**
   - **保存断点**：保存的是 **PC** 的值，即**程序执行到了哪里**。由**硬件**完成。
   - **保护现场**：保存的是 **通用寄存器和PSW** 的值，即**程序执行时的状态和数据**。由**软件**完成。
3. **中断向量表**
   - 一个存放在内存固定位置的数组，每个表项存储着一个中断服务程序的**入口地址**。
   - CPU通过**中断类型号**作为索引来查找这个表。
4. **多重中断（中断嵌套）**
   - 实现方式：在ISR中，保护现场后执行 **“开中断”** 指令。这样，在执行ISR的过程中，CPU就可以响应更高级别的中断请求。
   - 流程：ISR执行中被更高优先级中断打断 → 重复上述中断流程（硬件保存新断点等） → 执行新的ISR → 新的ISR返回 → 回到原来的ISR继续执行。
