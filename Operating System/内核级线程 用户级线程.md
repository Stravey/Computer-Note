# 用户级线程 内核级线程

### 一、核心概念

#### 1. 用户级线程 (ULT)

- **定义**：在**用户空间**实现的线程。线程的创建、撤销、同步、调度等所有管理工作都由**应用程序**通过**线程库**（如Linux的pthread库）完成，**内核感知不到这些线程的存在**。
- **内核视角**：从操作系统内核看来，只有一个**执行实体**（即一个进程，也就是一个内核级线程）。内核只负责为这个进程分配CPU和其他资源。
- **关键特性**：
  - **不涉及系统调用**：所有线程操作都在用户态下完成，效率高，速度快。
  - **内核无关性**：线程库可以在任何不支持多线程的操作系统上运行。
  - **自定义调度算法**：应用程序可以为自己量身定制线程调度算法（如先来先服务、优先级等），灵活性高。

#### 2. 内核级线程 (KLT)

- **定义**：线程的创建、撤销、同步、调度等管理工作全部由**操作系统内核**完成。内核为每一个线程维护一个**线程控制块（TCB）**。
- **内核视角**：内核能感知到每一个线程，并可以将它们调度到任何一个CPU核心上执行。
- **关键特性**：
  - **涉及系统调用**：线程操作（如创建）需要切换到内核态，由内核完成，开销比ULT大。
  - **内核感知**：内核知道所有线程，因此当一个线程阻塞时（如等待I/O），内核可以调度该进程内的其他就绪线程运行。
  - **利用多核**：内核可以将一个进程的多个线程真正并行地调度到多个CPU核心上。

### 二、二者对比

|  特性/方面   |                       用户级线程 (ULT)                       |                    内核级线程 (KLT)                     |
| :----------: | :----------------------------------------------------------: | :-----------------------------------------------------: |
|  **实现者**  |                    **应用程序**（线程库）                    |                    **操作系统内核**                     |
| **内核感知** |                **否**。内核只知道对应的进程。                |               **是**。内核管理每个线程。                |
|   **TCB**    |                  在**用户空间**由线程库维护                  |                 在**内核空间**由OS维护                  |
| **线程切换** |        **用户态**下完成，**无需模式切换**，**速度快**        |        需要**陷入内核**（模式切换），**速度慢**         |
| **调度单位** |                   **进程**是内核的调度单位                   |                **线程**是内核的调度单位                 |
|  **阻塞性**  | **一个线程阻塞会导致整个进程阻塞**（因为内核以为只有一个执行流） |    **一个线程阻塞，内核可调度该进程内其他就绪线程**     |
| **利用多核** |     **不能**。一个进程的多个ULT只能在一个CPU核心上运行。     |     **能**。可将多个KLT分配到不同CPU核心并行执行。      |
|   **优点**   |  1. 高效（无模式切换） 2. 灵活（自定义调度） 3. 可移植性好   | 1. 并发性好（线程阻塞不影响其他线程） 2. 能利用多核优势 |
|   **缺点**   |   1. **“阻塞”问题**（一个阻塞，全体阻塞） 2. 不能利用多核    |   1. 效率低（线程操作需陷入内核） 2. 占用更多内核资源   |

### 三、多线程模型 (Many-to-One, One-to-One, Many-to-Many)

这是连接ULT和KLT的桥梁，是408的绝对重点。

#### 1. 多对一模型 (Many-to-One Model)

- **描述**：将**多个**用户级线程映射到**一个**内核级线程。
- **实质**：就是纯粹的**用户级线程**实现。
- **优缺点**：同上文ULT的优缺点。**最大的缺点是无法实现真正的并行**。

#### 2. 一对一模型 (One-to-One Model)

- **描述**：将**每一个**用户级线程映射到**一个**内核级线程。
- **实质**：就是纯粹的**内核级线程**实现。
- **优缺点**：同上文KLT的优缺点。**最大的缺点是创建大量线程会给内核带来沉重负担**（如Windows，Linux的pthread默认采用此模型）。

#### 3. 多对多模型 (Many-to-Many Model)

- **描述**：将**多个**用户级线程映射到**同样数量或更少**的内核级线程上。
- **目的**：克服前两种模型的缺点，取长补短。
- **优点**：
  - **开发人员可以创建任意多的ULT**，不受内核资源限制。
  - 当某个ULT阻塞时，内核可以调度另一个KLT去执行其他ULT。
  - 可以将多个ULT分配到多个CPU核心上执行，实现真正的并行。
- **变种：两级模型 (Two-Level Model)**
  - 是多对多模型的变种，允许一个ULT与某个KLT**绑定**（类似于一对一），而其他ULT仍然实行多对多映射。提供了更大的灵活性。
