### **同步与互斥知识点详细总结**

#### **一、 核心概念**

1. **临界资源**：

   - **定义**：一次仅允许一个进程使用的资源。例如：打印机、共享变量、共享文件、共享数据结构等。
   - **特点**：虽然多个进程可以共享，但必须互斥地访问，否则会导致数据不一致或不明确的结果。

2. **临界区**：

   - **定义**：每个进程中访问临界资源的那段代码。
   - **结构**：每个进程在进入临界区之前，必须先请求许可；在退出临界区之后，必须释放资源。

   ```c++
   do {
       entry section;    // 进入区：申请权限
       critical section; // 临界区：访问资源
       exit section;     // 退出区：释放权限
       remainder section;// 剩余区：其他代码
   } while (true);
   ```

3. **互斥**：

   - **目标**：保证在任何时刻，**只有一个进程**处于其临界区内。它解决的是“竞争条件”问题。
   - **好比**：一个只有一个坑位的厕所，一次只能一个人用，用的时候要锁门。

4. **同步**：

   - **目标**：在多个进程之间建立一种**执行次序**上的协调关系。某个进程的执行需要等待另一个合作伙伴进程发来消息或信号。
   - **好比**：生产者和消费者，生产者生产了东西，消费者才能消费。消费者必须“等待”生产者。

**互斥是同步的一种特殊情况**。同步包含了互斥，但范围更广。

------

#### **二、 实现同步与互斥的机制**

实现同步与互斥的解决方案可以分为两大类：**软件方法**和**硬件方法**，最终演进为更高级的**信号量**和**管程**。

##### **1. 软件方法（算法）**

- **单标志法**：违背“空闲让进”原则。
- **双标志先检查**：违背“忙则等待”原则（由于进程可被随时中断，可能导致两个进程同时进入临界区）。
- **双标志后检查**：违背“空闲让进”和“有限等待”原则（可能导致“饥饿”甚至“死锁”）。
- **Peterson‘s Algorithm (皮特森算法)**：
  - **思想**：结合了“主动争取”和“主动谦让”。
  - 使用两个变量：`turn`（表示轮到谁）和 `flag[]`（表示谁想进入）。
  - 满足了同步互斥的四个准则（除“让权等待”），是**正确的软件算法**，但依赖于**忙等待**（自旋锁），浪费CPU。

##### **2. 硬件方法**

- **中断屏蔽**：
  - 在进入临界区前**关闭中断**，离开后再打开。
  - **优点**：简单。
  - **缺点**：权力太大，只适用于内核进程；不适用于多CPU系统（只能屏蔽当前CPU的中断）。
- **硬件指令（原子操作）**：
  - **TestAndSet (TSL/TAS) 指令**：原子地读出旧值并设置新值。
  - **Swap (XCHG) 指令**：原子地交换两个字的内容。
  - **优点**：实现简单，适用于任意数量的进程；支持多处理器。
  - **缺点**：**忙等待**，不满足“让权等待”，可能导致“饥饿”。

##### **3. 信号量机制 (核心重点)**

由Dijkstra提出，是一种功能强大的同步工具，通过两个**原子操作** `wait(S)`（P操作）和 `signal(S)`（V操作）来访问。

- **整型信号量**：

  - 一个整数，表示可用资源数量。
  - `wait(S)`: `while (S<=0); S--;` (存在忙等待)
  - `signal(S)`: `S++;`

- **记录型信号量**：

  - **解决了忙等待问题**，是实际操作系统中最常用的形式。

  - 数据结构包含：

    - `int value`：资源数量。
    - `struct process *L`：指向等待该资源的进程队列。

  - `wait(S)`:

    ```c++
    S.value--;
    if (S.value < 0) {
        block(S.L); // 自我阻塞，放弃CPU，进入等待队列
    }
    ```

  - `signal(S)`:

    ```c++
    S.value++;
    if (S.value <= 0) {
        wakeup(S.L); // 唤醒等待队列中的一个进程
    }
    ```

- **信号量的应用**：

  - **实现互斥**：设置一个初值为1的信号量（互斥锁，Mutex）。

    ```c++
    semaphore mutex = 1;
    Process Pi() {
        P(mutex);
        // 临界区
        V(mutex);
    }
    ```

  - **实现同步**：设置一个初值为0的信号量。

    ```c++
    // 进程A必须在进程B的X点之前完成
    semaphore syn = 0;
    Process A() {
        // ... do something ...
        V(syn); // 发信号，表示“我做完了”
    }
    Process B() {
        P(syn); // 等待信号，如果A没完成就阻塞
        // ... point X ...
    }
    ```

- **经典同步问题**（必须掌握）：

  - **生产者-消费者问题**：使用两个信号量（`empty`, `full`）和一个互斥信号量（`mutex`）。
  - **读者-写者问题**：读者优先 vs 写者优先。涉及计数和复杂的互斥关系。
  - **哲学家进餐问题**：典型的死锁场景。解决方案：资源分级、最多允许4人同时拿、同时拿起左右筷子（原子操作）。

##### **4. 管程 (Monitor)**

- **目的**：为了更易于编写正确的并发程序，将信号量及其操作封装起来，**隐藏同步细节**。
- **定义**：一个由过程、变量及数据结构等组成的一个集合。进程只能通过调用管程中的过程来间接访问共享数据。
- **特性**：
  - **互斥性**：任何时候只能有一个进程在管程中活动。编译器负责实现互斥，程序员无需关心。
  - **同步工具**：使用**条件变量**（`condition`）来实现同步。每个条件变量对应一个等待队列。
    - `c.wait()`：调用进程在条件c上阻塞，并释放管程的互斥权。
    - `c.signal()`：唤醒在条件c上阻塞的一个进程。如果没有，则什么也不做。

------

#### **三、 同步与互斥必须遵循的准则**

1. **空闲让进**：临界区空闲时，应允许一个请求进入的进程立即进入。
2. **忙则等待**：当已有进程在临界区时，其他试图进入的进程必须等待。
3. **有限等待**：对请求进入的进程，应保证在有限时间内能进入临界区（防止“饥饿”）。
4. **让权等待**：当进程不能进入临界区时，应立即释放处理器，防止“忙等待”。（这是衡量算法优劣的关键标准）

------

#### **四、 相关的重要问题**

1. **死锁**：
   - **关系**：同步与互斥是导致死锁的**必要条件**之一（互斥条件、请求和保持条件）。
   - **区别**：死锁是多个进程因竞争资源而陷入的**永久等待**状态；而同步互斥是正常的、可解的协调过程。错误的同步实现（如信号量使用不当）会导致死锁。
2. **饥饿**：
   - **关系**：一个进程由于优先级等原因，**始终得不到服务**（无法进入临界区）。同步机制设计不当（如非公平的信号量唤醒策略）会导致饥饿。

------

#### **五、 与其他知识点的关系**

1. **与进程管理的关系**：
   - 这是同步与互斥问题产生的**根源**。正是因为有了**进程并发**（并行/交替执行），才导致了竞争条件和执行顺序不确定的问题。进程是同步与互斥的服务对象和主体。
2. **与处理机调度的关系**：
   - 调度算法决定了进程的切换时机。在**进入区**或**退出区**进行进程切换，是导致软件算法失败（如双标志法）的原因。
   - “让权等待”准则直接依赖于调度程序：当一个进程在信号量上阻塞时，它主动引发调度，让出CPU。
3. **与死锁的关系**：
   - 如上所述，同步与互斥是死锁的诱因。例如，哲学家进餐问题就是同步问题直接导致死锁的经典案例。解决死锁的方法（如银行家算法）可以辅助设计更安全的同步方案。
4. **与内存管理的关系**：
   - 共享内存是实现进程间通信（IPC）的重要方式，而共享内存区域就是典型的**临界资源**。对共享内存的读写必须通过同步机制（如信号量）来保护。
5. **与文件系统的关系**：
   - 文件是一种共享资源。多个进程同时读写同一个文件需要同步。文件锁（读锁、写锁）就是文件系统层面提供的同步机制。
6. **与现代并发编程的关系**：
   - 同步与互斥的原理是现代多线程编程的基础。编程语言中的 `synchronized` 关键字（Java）、`Mutex` 和 `Condition Variable`（C++、Python）、`channel`（Go）等都是这些操作系统概念在高级语言中的实现和封装。
