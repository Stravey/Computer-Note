# CPU调度

### 📊 调度层次对比

CPU调度通常分为三个层次，它们协同工作：

|        调度层次         |    发生位置     |                           主要任务                           |  频率  |                   备注                   |
| :---------------------: | :-------------: | :----------------------------------------------------------: | :----: | :--------------------------------------: |
| **高级调度** (作业调度) |  外存 -> 内存   |    从后备作业中选择作业调入内存，为其创建PCB，准备竞争CPU    | **低** |          主要用于多道批处理系统          |
| **中级调度** (内存调度) |  内存 -> 外存   | 将暂时不能运行的进程调至外存挂起（挂起态），当条件具备时再重新调入内存 | **中** |     目的是提高内存利用率和系统吞吐量     |
| **低级调度** (进程调度) | 就绪队列 -> CPU |           从就绪队列中选择一个进程，将CPU分配给它            | **高** | **最基本、频率最高**的调度，几十毫秒一次 |

### ⏰ 进程调度的时机与方式

进程调度需要选择合适的时机进行，并且有不同的调度方式。

**1. 调度时机**

- **当前运行进程主动放弃CPU**：例如进程正常结束、运行中发生异常、主动请求阻塞（如等待I/O）。
- **当前运行进程被动放弃CPU**：例如分给进程的时间片用完、有更紧急的事情需要处理（如I/O中断）、有更高优先级的进程进入就绪队列 。
- **不能进行调度的情况**：在处理中断的过程中、进程在操作系统**内核临界区**中（访问内核数据结构，如就绪队列）、在进行原子操作（原语）的过程中 。需要注意的是，**访问普通临界资源（如打印机）时是可以进行调度的** 。

**2. 调度方式**

- **非剥夺调度方式（非抢占式）**：即使有更紧迫的任务到达，当前进程也一直运行直到它主动放弃CPU。**优点**是实现简单、系统开销小；**缺点**是无法及时处理紧急任务，适用于早期的批处理系统 。
- **剥夺调度方式（抢占式）**：允许操作系统强制剥夺当前运行进程的CPU，分配给更重要的进程。**优点**是可以优先处理紧急任务，也能实现时间片轮转，适用于分时系统、实时系统 。

### 📈 经典调度算法

不同的调度算法适用于不同的场景，各有优缺点。

|       算法名称        |                           主要思想                           |            优点            |                    缺点                    |      适用场景      |
| :-------------------: | :----------------------------------------------------------: | :------------------------: | :----------------------------------------: | :----------------: |
| **先来先服务** (FCFS) |              按作业/进程到达的先后顺序进行调度               |       公平，实现简单       |       对短作业不利，平均等待时间较长       |   早期批处理系统   |
| **短作业优先** (SJF)  |             优先调度估计运行时间最短的作业/进程              |      平均等待时间最短      |      对长作业不利，可能导致“饥饿”现象      |     批处理系统     |
|    **优先级调度**     |        为每个进程分配一个优先级，按优先级高低进行调度        |    能处理紧急任务，灵活    | 若优先级设置不当，可能导致低优先级进程饥饿 | 实时系统、通用系统 |
|   **高响应比优先**    | 响应比 = (等待时间 + 要求服务时间) / 要求服务时间，选择响应比最高的进程运行 |   兼顾等待时间和服务时间   |             计算响应比增加开销             |     批处理系统     |
|  **时间片轮转** (RR)  |   为每个进程分配一个时间片，时间片用完后剥夺CPU并重新排队    |    公平，适用于分时系统    |           时间片大小选择影响性能           |      分时系统      |
|   **多级反馈队列**    | 设置多个优先级不同的就绪队列，新进程进入最高优先级队列，未能执行完的进程降级 | 兼顾多种类型进程，通用性好 |                  配置复杂                  |    通用操作系统    |

### 🧐 调度算法的评价指标

评价一个调度算法的优劣，通常参考以下指标：

- **CPU利用率**：CPU处于“忙”状态的时间比例。
- **系统吞吐量**：单位时间内完成的作业数量。
- **周转时间**：从作业提交到作业完成所经历的时间。
  - 平均周转时间：各作业周转时间的平均值。
  - 带权周转时间：作业周转时间与作业实际运行时间的比值。
- **等待时间**：进程处于等待（就绪队列中）CPU状态的时间之和。
- **响应时间**：从用户提交请求到系统首次产生响应（而不是输出结果）所用的时间。这对于交互式系统尤为重要。

### 🔄 进程的切换与过程

进程调度和切换是不同的概念。调度是**选择**一个新进程，而切换是**执行**这个选择的过程，即让选中的进程运行。切换过程需要：

1. **保存当前进程的上下文**（如程序计数器、寄存器等）到其PCB中。
2. **恢复新进程的上下文**。
3. 将CPU的控制权交给新进程。

**进程切换是有代价的**，需要一定的时间开销，过于频繁的进程切换会导致系统效率下降。





### 一、与操作系统内部的联系

#### 1. 与进程管理（进程状态转换）的联系

这是最直接、最紧密的联系。

- **调度是状态转换的触发器**：`就绪 -> 运行` 的状态转换正是由**低级调度（进程调度）** 引发的。调度程序从就绪队列中选择一个进程，为其分配CPU。
- **状态转换是调度的前提**：`运行 -> 阻塞` 是进程**主动**放弃CPU（如等待I/O），这立即创造了一次调度机会。`阻塞 -> 就绪` 是事件完成（如I/O完成），进程被**被动**地加入就绪队列，成为了下次调度可能的候选者。
- **真题角度**：题目常将进程状态图与调度算法结合考查。例如，给出一个进程序列和它们的I/O请求时间，问在FCFS或RR算法下，某个时间点CPU正在执行哪个进程，或者平均周转时间是多少。

#### 2. 与进程同步互斥（PV操作）的联系

- **竞争条件**：调度器的存在（随时可能发生进程切换）是导致竞争条件的根本原因。假设进程A和B共享一个变量，A在修改变量的过程中（非原子操作）可能被调度器剥夺CPU，此时B被调度运行并访问该变量，就会导致数据不一致。
- **临界区的设计**：正因为调度是**抢占式**的，所以我们才需要**互斥锁**等同步机制来保护临界区。锁的本质就是在临界区代码段内“**禁止调度**”或“**让其他进程自愿等待**”，从而保证原子性。
- **真题角度**：常给出一段有并发问题的代码，问为什么出错（根本原因就是调度导致的指令交错执行），并要求用PV操作进行改正。

#### 3. 与死锁的联系

- **资源分配与调度**：调度程序负责分配**CPU**资源，而死锁涉及的是对**I/O设备、内存**等资源的竞争。两者共同构成了系统的资源分配策略。
- **饥饿 vs 死锁**：不好的调度策略（如非抢占式的优先级调度）可能导致**低优先级进程永远得不到CPU**，这就是“饥饿”。它和死锁（多个进程互相等待对方持有的资源）都是系统的不稳定状态，但成因不同。这是一个重要的辨析点。

#### 4. 与内存管理的联系（中级调度）

- **交换技术**：**中级调度**（内存调度）负责将暂时不运行的进程从内存**换出**到外存（挂起态），以腾出内存空间。当这些进程被重新**换入**内存时，它们才重新有资格参与CPU调度（低级调度）。
- **工作集模型**：一个进程如果频繁地被换出换入（抖动），其缺页率会极高，有效执行时间很少。一个好的调度器需要与内存管理器配合，考虑进程的“工作集”，避免频繁调度一个正在发生抖动的进程，否则会恶化系统性能。

### 二、与计算机组成原理（COA）的联系

这是体现408科目交叉综合能力的关键。

#### 1. 与中断机制的联系

- **调度发生的时机**：绝大多数**抢占式调度**的发生都是由**中断**触发的！
  - **时钟中断**：导致**时间片用完**，当前进程被剥夺CPU，调度程序启动。
  - **I/O中断**：**I/O完成**时，会中断CPU，内核处理中断后，会将等待该I/O的进程从阻塞态转为就绪态。这个新就绪的进程可能优先级更高，从而引发调度。
- **过程**：`中断发生 -> 硬件保护现场 -> 转入中断处理程序 -> 中断处理程序中可能调用调度程序 -> 调度程序选择新进程 -> 恢复新进程的现场并执行`。

#### 2. 与上下文切换（现场保护）的联系

- **上下文是什么**：上下文就是进程的运行环境，主要是**寄存器**的值（PC, SP, 通用寄存器等）和程序状态字（PSW）。
- **切换的代价**：**进程切换**需要保存旧进程的上下文到其PCB中，并加载新进程的上下文到寄存器中。这个操作由**硬件辅助**完成，但依然有显著的时间开销。这正是时间片不能设置得太小的原因。

#### 3. 与局部性原理和Cache的联系

- **Cache污染**：当进程切换后，新进程几乎会**污染**原进程在Cache中的数据。因为新进程的指令和数据与原进程不同，导致Cache命中率急剧下降。
- **调度算法的影响**：因此，在设计调度算法时（特别是多处理器调度），会考虑**affinity（亲和性）**，即尽量让一个进程再次在同一个CPU核心上运行，这样它之前Cache的数据可能还有效，可以提高性能。

### 三、与数据结构的联系

调度算法的实现严重依赖于数据结构。

- **就绪队列**：本质上是一个**队列**数据结构。
  - FCFS算法使用一个简单的**FIFO队列**。
  - SJF/优先级调度算法使用**优先队列**（通常用**堆**来实现），以便高效地取出最短作业或最高优先级的进程。
  - 多级反馈队列（MLFQ）则维护了**多个队列**。
- **PCB的组织**：操作系统内核中所有进程的PCB通常通过**链表**进行组织，就绪队列、阻塞队列都是PCB链表。
