# Inode

### 一、inode 是什么？

**inode**（index node，索引节点）是类Unix/Linux文件系统中用于**描述一个文件或目录的元数据（metadata）的数据结构**。

你可以把它理解成一个文件的“**身份证**”或“**户口本**”。它**并不存储文件的实际数据内容**，而是存储关于该文件的几乎所有信息（除了文件名）。

### 二、inode 包含哪些信息？（核心内容）

一个 inode 通常包含以下元数据信息，这些是考试和实际工作中的重点：

1. **文件大小**：文件的字节数。
2. **设备ID**：文件所在的设备标识。
3. **文件所有者**：即 User ID (UID)。
4. **文件所属组**：即 Group ID (GID)。
5. **文件权限**：读、写、执行的权限（rwx for user, group, others）。
6. **时间戳**：
   - **ctime**：inode 状态变更时间（如修改权限、所有者）。
   - **mtime**：文件**内容**修改时间。
   - **atime**：文件最后**访问**时间。
7. **链接数**：指向该 inode 的目录项（dentry）的数量。这是理解硬链接的关键。
8. **数据块指针**：这是 **inode 最核心的功能**！它存储了指向磁盘上哪些**数据块（Block）** 包含了该文件实际内容的位置信息。指针结构经过精心设计以支持不同大小的文件。

### 三、inode 如何定位文件数据？—— 指针结构

inode 不存数据，只存指针。它采用了一种多级索引的结构来高效地管理大文件和小文件。

1. **直接指针**：
   - inode 中直接包含若干个（如12个）指向数据块的指针。
   - 对于小文件（比如 < 12 * 4KB = 48KB），直接通过这些指针就能找到所有数据块，速度极快。
2. **一级间接指针**：
   - inode 中有一个指针，它不指向数据块，而是指向一个**指针块**。
   - 这个指针块里存放的都是直接指向数据块的指针。
   - 假设一个指针4字节，一个块4KB，那么这个指针块可以存放 1024 个指针。可以管理 1024 * 4KB = 4MB 的数据。
3. **二级间接指针**：
   - inode 中有一个指针，指向一个**一级指针块**，这个一级指针块里的每个指针又各自指向一个**二级指针块**，二级指针块里的指针才指向真正的数据块。
   - 可以管理 1024 * 1024 * 4KB = 4GB 的数据。
4. **三级间接指针**：
   - 依此类推，层级更多，用于管理非常大的文件。
   - 可以管理 1024 * 1024 * 1024 * 4KB = 4TB 的数据。

**这种设计的优点**：既保证了小文件的访问效率（只需1次磁盘访问），又支持了超大文件的存储，是一种典型的时间与空间的权衡（Trade-off）。

### 四、inode 与文件名、目录的关系

这是最容易混淆的点，务必理解清楚：

- **文件名 ≠ 文件本身**。文件名只是为了方便用户记忆和使用。

- **目录的本质**：目录本身也是一个文件，它的内容非常简单，就是一个**映射表**，记录了**文件名**到 **inode 编号**的映射。

  - 例如，目录文件 `/home` 的内容可能看起来像这样：

    |     文件名     | inode编号 |
    | :------------: | :-------: |
    |    `user1`     |  1048576  |
    |    `user2`     |  1048577  |
    | `document.pdf` |  1234567  |

- **访问文件的流程**：

  1. 用户在 shell 中输入 `cat /home/user1/test.txt`。
  2. 系统首先在根目录 `/` 的目录项中找到文件名 `home` 对应的 inode 编号。
  3. 根据该 inode 编号找到 `/home` 目录的 inode，验证权限，然后读取 `/home` 目录的数据块内容。
  4. 在 `/home` 目录的数据块中查找文件名 `user1` 对应的 inode 编号。
  5. 根据该 inode 编号找到 `/home/user1` 目录的 inode，读取其数据块内容。
  6. 在 `/home/user1` 的数据块中查找文件名 `test.txt` 对应的 inode 编号，假设是 `9876`。
  7. **最终步骤**：找到 inode 编号 `9876` 对应的 inode，从中读取文件的元信息（权限、大小等）和**数据块指针**，最后根据指针去磁盘上读取文件的实际内容。

**结论**：文件系统通过 inode 编号来唯一标识和操作文件，文件名只是给用户看的一个“别名”。

### 五、硬链接与软链接（符号链接）

这个知识点直接源于 inode 机制。

|      特性      |                    **硬链接 (Hard Link)**                    |            **软链接 (Symbolic Link / Soft Link)**            |
| :------------: | :----------------------------------------------------------: | :----------------------------------------------------------: |
|    **本质**    |         是**同一个 inode** 的多个**目录项**（别名）          |           是一个**独立的文件**，有自己独立的 inode           |
|   **inode**    |              **与源文件共享相同的 inode 编号**               |                    拥有自己的 inode 编号                     |
|    **命令**    |                  `ln source_file hard_link`                  |                `ln -s source_file soft_link`                 |
| **删除源文件** | **不影响**硬链接的访问。inode 的链接数减1，只要链接数不为0，数据块就不会被释放。 | **失效**。软链接将变成“悬空链接”（Dangling link），指向一个不存在的文件。 |
| **跨文件系统** |     **不支持**。因为 inode 编号在不同文件系统中不唯一。      |             **支持**。因为它存储的是路径字符串。             |
|   **链接数**   |            创建硬链接，inode 的**链接数会增加**。            |             创建软链接，源文件的链接数**不变**。             |
|  **文件类型**  |                   和源文件一样，是普通文件                   |      是特殊的链接文件（`l`类型，`ls -l` 首字符为 `l`）       |
|    **大小**    |                       与源文件大小相同                       |               大小是**源文件路径名的字节长度**               |

### 六、重要命令与实践

1. **查看 inode 信息**：

   - `ls -i`：显示文件和目录的 inode 编号。

     bash

     ```
     ls -i test.txt
     1234567 test.txt
     ```

     

   - `stat`：显示文件或目录的 inode 中所有元数据信息。

     bash

     ```
     stat test.txt
       File: test.txt
       Size: 1024        Blocks: 8          IO Block: 4096   regular file
     Device: fd01h/64769d    Inode: 1234567     Links: 1
     Access: (0644/-rw-r--r--)  Uid: ( 1000/   user)   Gid: ( 1000/   user)
     Access: 2023-10-27 10:00:00.000000000 +0800
     Modify: 2023-10-27 09:00:00.000000000 +0800
     Change: 2023-10-27 09:00:00.000000000 +0800
     ```

     

2. **查看文件系统 inode 使用情况**：

   - `df -i`：显示每个磁盘分区的 inode 总数、已用数、空闲数和使用百分比。

     bash

     ```
     df -i
     Filesystem      Inodes  IUsed   IFree IUse% Mounted on
     /dev/sda1      6553600 123456 6430144    2% /
     ```

     

   - 即使磁盘空间（`df -h`）还有剩余，如果 inode 被耗尽（`IUse% 100%`），也无法创建新文件。

### 七、总结与考点

1. **核心概念**：inode 是存储**元数据**的结构，**不存**文件数据。
2. **关键数据**：权限、所有者、时间戳、**链接数**、**数据块指针**。
3. **指针结构**：理解直接、一级间接、二级间接指针的**设计目的和工作原理**（常考选择题或大题）。
4. **文件访问流程**：理解如何通过**文件名→目录项→inode编号→inode→数据块**的路径找到文件内容。
5. **硬链接 vs 软链接**：这是 inode 机制的直接应用，**必须熟练掌握区别**（常考选择题）。
6. **inode 耗尽问题**：理解 `df -i` 命令的含义和 inode 耗尽的影响。
