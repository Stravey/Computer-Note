# IPV6与IPV4

#### 1. 地址空间：根本性的区别

这是最核心、最广为人知的区别。

- **IPv4**：使用 32 位地址，理论上提供 $2^{32}$ (4,294,967,296) 个地址。由于历史分配和低效利用，实际可用地址早已耗尽。
- **IPv6**：使用 128 位地址，理论上提供 $2^{128}$ (约 3.4×10³⁸) 个地址。这个数量级使得地址枯竭问题在可预见的未来不再发生。

#### 2. 地址格式与书写方式

- **IPv4**：
  - 格式：4 个 8 位的十进制数，用点 (.) 分隔。
  - 示例：`192.168.10.1`
- **IPv6**：
  - 格式：8 个 16 位的十六进制数，用冒号 (:) 分隔。
  - 示例：`2001:0db8:85a3:0000:0000:8a2e:0370:7334`
  - **简化规则**：
    - **前导零省略**：`2001:0db8:...` 可写为 `2001:db8:...`
    - **连续零压缩**：一连串的 `0000` 可以用 **双冒号 `::`** 代替，但**在一个地址中只能使用一次**。
    - **简化后示例**：上面的地址可简写为 `2001:db8:85a3::8a2e:370:7334`

#### 3. 报头结构：效率的提升

IPv6 对数据包头部进行了大幅简化，提高了路由器的处理效率。

- **IPv4 报头**：包含 **12** 个字段，长度不固定（20-60字节），包含“选项”字段，路由器需要检查所有字段，处理开销大。
- **IPv6 报头**：包含 **8** 个字段，长度固定为 **40 字节**。去掉了不必要的字段（如首部校验和、分片相关字段），并将可选字段放在“扩展报头”中。路由器只需处理基本报头，速度更快。

#### 4. 地址类型与通信方式

- **IPv4**：
  - **单播 (Unicast)**：一对一通信。
  - **广播 (Broadcast)**：一对所有（同一广播域内）。ARP 协议严重依赖广播，会造成网络带宽浪费（广播风暴）。
  - **组播 (Multicast)**：一对一组。
- **IPv6**：
  - **单播 (Unicast)**：一对一通信。
  - **组播 (Multicast)**：一对一组。**功能大大增强**，取代了 IPv4 的广播。所有节点都默认加入多个组播组。
  - **任播 (Anycast)**：一对一组中**最近的一个**。这是 IPv6 中正式定义的重要特性，可用于寻找最近的 DNS 服务器、网关等，提升服务效率。
  - **取消了广播**：ARP 被 **ICMPv6 邻居发现协议 (NDP)** 取代，NDP 使用组播报文，更加高效。

#### 5. 网络配置：即插即用

- **IPv4**：通常需要一台 DHCP 服务器来为客户机自动分配 IP 地址、网关、DNS 等信息（动态配置）。也可以手动配置（静态配置）。
- **IPv6**：
  - **无状态地址自动配置 (SLAAC)**：这是 IPv6 的一大亮点。主机可以通过接收路由器发出的**路由器通告 (RA)** 消息，结合自身的**接口标识符**（通常由 MAC 地址生成），自动生成一个全球唯一的 IPv6 地址，并获取网关等信息。完全不需要 DHCP 服务器。
  - **DHCPv6**：当需要分配 DNS 服务器等更多信息时，也可以使用 DHCPv6（有状态配置）。

#### 6. 安全性：原生集成

- **IPv4**：IPSec 是一个可选的加密和认证扩展协议，并非所有设备都支持。
- **IPv6**：**IPSec 是协议套件内置的一部分**。RFC 规定所有完整的 IPv6 实现都必须支持 IPSec。这为端到端的安全通信提供了基础设施保障，虽然在实际应用中，是否使用仍需配置。

#### 7. 与 IPv4 的共存与过渡

由于 IPv4 和 IPv6 不直接兼容，互联网正在从一个协议向另一个协议漫长过渡。因此产生了多种**过渡技术**：

- **双栈 (Dual Stack)**：设备同时运行 IPv4 和 IPv6 协议栈，可以同时与两种网络通信。
- **隧道 (Tunneling)**：将 IPv6 数据包封装在 IPv4 数据包中，在 IPv4 网络中传输（如 6to4, Teredo）。
- **协议转换 (Translation)**：在 IPv4 和 IPv6 网络之间进行协议转换（如 NAT64）。
